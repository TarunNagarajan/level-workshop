# Difficulty collection API

All routes below are under `/api`. Collection management, module/taxonomy inspection, reviews, summaries, exports, and previews require an authenticated workshop member. Collection entry and participant routes use an unguessable collection link and per-round capability instead. Responses never include provider API keys. The collection snapshot pins a saved scenario version, provider model/endpoint/reasoning settings, module catalogue version, eight profile definitions, and each compiled prompt. A trial changes only its assigned protection profile; scenario, provider settings, temperature, and duration stay fixed.

## Modules and review labels

`GET /difficulty-modules` returns `{version, modules, profiles}`. The version identifies the protection-module catalogue. `modules` describes the available instruction layers; `profiles` contains the eight built-in profiles. A custom profile consists of `{id, label, notes, moduleIds, additionalInstructions}`. IDs and module IDs are validated; each profile's compiled prompt is saved into the collection snapshot.

`GET /difficulty-taxonomy` returns `{attemptedStrategies, observedFailures}`. Each item is a list of `[id, label]` pairs. Collection review accepts only IDs from these lists. Observed target failures require evidence from a non-opening assistant reply, apart from `provider_issue`, `confusing_clue`, and `other_failure`, which can describe non-transcript events.

## Collections and frozen snapshots

`GET /collections?limit=50&cursor=...` returns `{collections, limit, nextCursor}`. The limit is an integer from 1 through 100. Each item is compact: `{id, ownerId, sourceLevelId, sourceVersionId, title, mode, version, profiles:[{id,label,moduleIds}], status, revision, createdAt}`. The opaque cursor keeps paging within the original creation-time cutoff.

`POST /collections` accepts `{levelId, versionId, profiles?}` and returns `201` with `{id, ownerId, status, revision, createdAt, snapshot}`. When omitted, `profiles` uses the eight built-in profiles; a collection can freeze from 1 through 12 custom or selected profiles. The reference passport source must use the canonical `reference-passport-desk-v1` version, and any member can create a collection from that immutable reference. For other scenarios, the source must be owned by the member or accessible to the workspace owner. Only the collection creator or workspace owner can change admission, links, and previews.

The authenticated `GET /collections/:id` returns `{id,ownerId,sourceLevelId,sourceVersionId,snapshot,status,revision,createdAt,profileCounts,canManage,links?}`. `snapshot` is the full author-only snapshot; `profileCounts` is `[{profileId,allocated}]`; managers receive `links:[{id,createdAt,expires,revoked}]`. The snapshot includes the source scenario and compiled profiles and is not returned to participants.

`PATCH /collections/:id/status` accepts `{status:"active"|"paused",revision}` and returns the new status and incremented revision. A stale revision returns `409`. Pausing stops new admissions, but existing participants retain their resume capability. `POST /collections/:id/links` accepts optional `{days}` from 1 to 90 and returns `201 {id,path,createdAt,expires}`. The raw bearer token appears only in `path` at creation; only its hash is stored. `DELETE /collections/:id/links/:linkId` revokes it and returns `{ok:true}`.

## Blind entry and recovery

`GET /collect/:token` returns a participant-safe briefing: `{level,connected,kind,consentTextVersion,accepting,isPassport,documents?}`. `kind` is `conversation` or `passport`. It does not reveal profile assignment, protection instructions, secret truth, author notes, or provider settings. A valid but paused, revoked, or expired link returns the briefing with `accepting:false`; an unknown token returns `404`.

`POST /collect/:token` requires `{tester,consent:true,startKey}`. `startKey` must be a random UUIDv4 and must be retained by the browser before the first request. A new accepted admission returns `201`; retrying the same link and start key returns `200` with the same round and capability, even if the collection was later paused or the link revoked/expired. A different key cannot recover or list that assignment. Retry the same request after a network error; do not mint a replacement key until there is no prior accepted receipt to resume. Allocation is balanced toward the least-assigned profiles with ties chosen securely. Failed races do not create a partial round or assignment.

For a conversation, the response is `{kind:"conversation",round}`. For the passport desk it is `{kind:"passport",round,state,documents}`. `round` is a participant-safe DTO: `{id,level,tester,messages,startedAt,endedAt,deadline,answer,hintsUsed,source,accessToken}`. It omits the provider model, saved version, source scenario data, and request context. Message entries contain only `{id,role,content,createdAt,opening?,latencyMs?}`. Model-spoken content is preserved as produced. Keep the returned capability private.

Resume a saved conversation with `GET /rounds/:id` and header `x-round-token: <accessToken>`. Resume a passport with `GET /reference/rounds/:id` and the same header. Passport actions and messages use `/reference/rounds/:id/action` and `/reference/rounds/:id/messages`; these run the real interactive desk and pass server-verified desk observations to the frozen profile prompt. Author-only context inspection is unavailable to participants. Accepted sessions remain resumable after collection pause or link revocation.

## Author previews

`POST /collections/:id/previews` accepts `{profileId}` and returns `201`. A conversation preview is `{kind:"conversation",round,preview:true,profileId,profileLabel}`. A passport preview is `{kind:"passport",round,state,documents,preview:true,profileId,profileLabel}`. These are author sessions using the collection's frozen scenario, provider config, and profile. Preview assignments are marked separately and excluded from participant allocation and participant outcome distributions. Normal legacy active-round lookups exclude all collection-assigned rounds; previews should be reopened from the collection.

## Attempts and summary

`GET /collections/:id/attempts?limit=50&cursor=...&profileId=...` returns `{attempts,limit,nextCursor}` with limit 1 through 200. Attempt items include `{id,roundId,profileId,profile,source,assignedAt,tester,version,startedAt,endedAt,answer,finding?,decision?,hintsUsed,messages,review,annotation,providerCalls,passport?}`. `finding` and `decision` are derived for filed passport cases. `review` is the latest outcome/note/evidence record or `null`; `annotation` contains attempted strategy IDs, observed failure IDs, note, and update time or `null`; `providerCalls` is the safe array `[{status,startedAt,completedAt,latencyMs,errorCode}]` without model request content. The optional passport snapshot includes `revision,page,lamp,cardRequested,presented,selected,compared,hintsUsed,positions,events,decision,evidence`; each event has `{id,at,action,object,value,page,observation}`. It is present only for desk scenarios. The `profileId` filter is optional. Paging is stable against later insertions. Stale provider starts without a live round lease are marked `interrupted` before the page is returned.

`GET /collections/:id/summary` returns `{collectionId,status,revision,invariant,profiles,denominators}`. The invariant reports the shared scenario version, model, endpoint, temperature, and duration. Per-profile rows include participant allocations, preview count, branch/replay diagnostic counts, submitted/active/expired participant counts, review coverage and reviewed solved/partial/unsolved outcomes, provider request/trial failures, median solved submission time/questions/hints, and separate participant, preview, branch, and replay strategy/failure distributions. Branches and replays preserve profile lineage but never enter participant denominators. Outcome counts use reviewed participant attempts only. Provider failures are tracked independently and are not treated as defense failures. Expired provider calls whose round lease is gone are reconciled as interrupted.

## Review

`POST /collections/:id/review/:roundId` accepts `{outcome,note,evidence,annotation?}`. `outcome` is `solved`, `partial`, or `unsolved`; `evidence` is an array of message IDs and must point to target assistant replies, not the opening message. Solved and partial outcomes require evidence. An optional annotation is `{attemptedStrategies:[ids],observedFailures:[ids],note}`. A nonempty observed failure requires target evidence except for provider/usability/other failure categories. The response is `{ok:true,updatedAt}`. Replacing the legacy review clears its collection annotation; replacing a collection review without `annotation` also clears prior tags atomically.

## Export and privacy

`GET /collections/:id/export?limit=100&cursor=...&includeAuthor=false` returns a page with `{schema,schemaVersion,collectionId,cutoff,includeAuthor,provenance,trials,nextCursor,pageLimit}`. Limit is an integer from 1 through 200. Continue until `nextCursor` is `null`; there is no hidden result ceiling. The cursor fixes a time cutoff so later assignments cannot shift subsequent pages.

By default, export omits full scenario truth, compiled prompts, freeform profile notes/instructions, tester names, provider request contexts, credentials, private author configuration, and nested saved request/context fields. It retains safe scenario identifiers, catalogue version, profile IDs/labels/module IDs, nonsecret frozen provider model/endpoint/reasoning/temperature provenance, transcript, reviews, annotations, passport actions/state, and provider call status/error category/latency. `includeAuthor=true` returns the full author snapshot, profile notes, compiled prompts, scenario, provider configuration, and provider request contexts (`{baseUrl,body}`) to authenticated members. The recorded body is built by the same function used by the provider adapter, including supported reasoning settings. Never publish that form as participant output or include it in public reports without review.

## Failure behavior

Validation failures return `400`; unauthenticated management requests return `401`; unauthorized author-only access returns `403`; stale revisions, active allocation contention, or failed allocation guards return `409`; invalid/unknown links return `404`; paused links or attempts to create a new admission after pause return `410`; frozen provider configuration mismatch returns `503`. Provider-call records use stable error categories such as `rate_limited`, `timeout`, `provider_unavailable`, `provider_auth`, `provider_rejected`, `empty_response`, and `provider_configuration_changed`. A failed provider turn is not saved as a user transcript message and can be retried; an accepted participant assignment is not duplicated by retry.
