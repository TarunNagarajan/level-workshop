# Inception provider capacity

When `INCEPTION_AUTO_PROVIDER=true`, new Inception rounds select the first eligible configured slot in order: primary Groq, secondary Groq, then Gemma (Google Gemini). `GROQ_SECONDARY_API_KEY` is optional and must belong to a distinct approved Groq account; its base URL is fixed to `https://api.groq.com/openai/v1`. It uses the same GPT-OSS 20B model. If the secondary key is absent or duplicates the primary key, the slot is ignored. `INCEPTION_GROQ_DAILY_TOKEN_BUDGET` and `INCEPTION_GROQ_SECONDARY_DAILY_TOKEN_BUDGET` are independent application planning caps, each defaulting to 200,000. These caps do not establish provider entitlements or actual quota.

Each Groq account has independent usage, quota observations, cooldowns, and reservations. A rate limit on one account does not block the other. A new round reserves 10,000 tokens from the selected Groq slot. Unknown provider quota can use the same application-cap policy as the primary slot. Existing rounds with valid primary Groq snapshots remain routable.

An ongoing round may move forward from primary Groq to secondary Groq and then Gemma. A round already using secondary Groq may move to Gemma. A saved transition is durable for the rest of the round, so later targets and the judge use the selected slot. Each transition records the original provider/model selection and up to two forward hops, including role, reason, and time. A transition CAS checks the round config and unexpired lock; speculative reservations are bound to that round and released on CAS loss. Later requests reconcile stale reservations, and review releases all round reservations idempotently.

Fallback is limited to rate limits, timeouts, provider outages, authentication failures, and empty responses. Refusals, rejected requests, validation errors, config mismatches, persistence errors, and authorization/input errors do not trigger a switch. The same prompt, transcript, scene context, and submission ID are sent to the next provider. No partial response is appended. Every actual provider attempt records its safe slot label; keys and account identifiers are not stored in round data, metrics, exports, or logs.

Routing uses a monotonic total budget with request timeouts that reserve time for database work and transcript persistence. A configured three-slot route caps each attempt at about eight seconds and the full route at 25 seconds. Two-slot routes retain up to 15 seconds per attempt within a 31-second route budget. A single-provider route retains up to 30 seconds. An existing Gemma selection remains on Gemma with its 30-second timeout. Network calls are aborted at their actual per-attempt timeout, and each call rechecks the round config and lease immediately before dispatch.

The admin provider status reports each slot separately, with cooldown, observed quota, application budget, usage, and active reservations. The aggregate application planning capacity is explicitly the sum of independent app caps, not provider quota. The primary `applicationDailyBudget` status fields remain available for compatibility. With `INCEPTION_AUTO_PROVIDER` off, routing retains the existing primary Groq path.
