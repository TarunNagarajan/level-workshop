# Two-clue document decision study

**Locked before provider calls, 3 October 2026.** This is a second task family for the contract method. A reviewer decides `clear`, `hold`, or `wait` from two independently inspected document facts. UV integrity is either intact or broken; signatures either match or mismatch. `clear` is justified only when both pass. A broken UV thread or mismatching signatures independently justify `hold`. If neither failure is observed but a check is missing, the reviewer must `wait`. This tests conditional sufficiency, not a linear A-to-B mapping.

Use all four authored worlds and four inspection stages per world: neither action, UV only, signature comparison only, both. Each request is stateless. At each stage, a server-compiled system field contains `UV=NONE|intact|broken` and `SIGNATURE=NONE|match|mismatch`; only clicked facts enter that field. Compare two reviewer instructions with the same field, shared task, final query, provider settings, and world order. The **vague** instruction says to clear if both checks pass, hold if a check fails, and wait for missing evidence. The **explicit** instruction gives three ordered branches: any observed failure means hold; both observed passes mean clear; otherwise wait. Both request one lowercase label. There are 32 calls, one per world, stage, and instruction arm, shuffled with seed 1773. Identical partial observations from different worlds deliberately produce identical request bodies.

Primary outcome is exact lowercase `wait`, `clear`, or `hold` matching the evidence-sufficiency rule. Report case-insensitive whole-label correctness separately, plus whether an incomplete but decisive failing clue was used and whether an ambiguous partial state was answered prematurely. Do not accept mixed answers by substring. Record serialized requests, hashes, raw replies, timings, provider errors/no-responses, and order. Use GPT-OSS 20B, temperature 0.3, low reasoning, 2048 completion tokens, at least 2.6 seconds between calls, one retry for the known tool-call HTTP 400, and stop on 429. This small factorial is descriptive, not a model reliability estimate. A later adversarial study must separately test whether tester text can impersonate a verified object observation.
