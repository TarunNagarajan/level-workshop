# Author diagnosis study: prepared protocol

**Prepared 3 October 2026; no participants run yet.** The question is whether the paired-world author audit helps level builders locate and repair an unintended early reveal, compared with exploring the same paired player screenshots without the audit explanation. This is a formative usability check for the sandbox, not a model-security benchmark or a statistical claim about developers generally.

Use the local [equipment inspector](equipment-author-inspector.html). Give every participant a short clean-path orientation in which voltage first appears after opening the panel and measuring it. Then assign two 7-minute tasks: one with the intended fuse-inspection reveal and one with the intended voltage-meter reveal. In the **player-view** condition, the inspector hides world IDs and channel verdicts but retains the paired screenshots and action timeline. In the **author-audit** condition, it shows the first-difference channel list, named worlds, and early-exposure verdict. The assignment links lock the scenario and hide its diagnostic name in either condition. Do not show the answer key or the seeded fault switch names in task instructions; use neutral labels “Task A” and “Task B.”

Counterbalance task, condition, and order across four assignments, with two participants per assignment if eight collaborators are available: (1) fuse/player then clipboard/audit; (2) fuse/audit then clipboard/player; (3) clipboard/player then fuse/audit; (4) clipboard/audit then fuse/player. If fewer participate, report the actual allocation and avoid a treatment-effect claim. For each task, record a pseudonymous participant ID, assignment, start/submission times, first offending action, observation channel, proposed code or rule change, confidence from 1 to 5, and whether the participant used the image zoom. Collect no API keys, prompt secrets, or personal names. Ask a final open question about what the audit explained or obscured.

Grade each task against a fixed three-part rubric, one point each: correct earliest action, correct affected observation channel, and a repair that removes the early path while preserving the intended inspection reveal. Record partially correct diagnoses, timeouts, and unused time separately. Score before looking at condition labels if a second reviewer is available. Compare within-person accuracy and time descriptively; with this sample, do not claim population-level significance. Report both the successes and confusions that would require changing the author UI. The [answer key](equipment-author-study-answer-key.md) is held back from participants.

The current local prototype passed desktop/mobile Chromium interaction checks and screenshots, but it has not been deployed for participants. A real run still needs participant consent, fixed task links or a facilitator, and saved responses. Browser automation verifies that controls work; it is not human usability evidence.
