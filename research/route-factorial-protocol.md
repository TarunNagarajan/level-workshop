# Route handoff study protocol

**Locked before the expanded run, 3 October 2026.** This is a small engineering experiment, not a publication-scale benchmark. The dataset and scoring below are fixed before observing the new responses.

The question is whether the route planner's failure to use an authentic natural-language handoff in the two-world pilot was caused by where the same sentence was delivered, or by the protocol's wording and state representation. Eight authored delivery cases each have two possible open routes, distinct correct vehicle names, and identical downstream pre-handoff inputs within the pair. The route specialist's answer is supplied as an oracle artifact for this experiment, so the test isolates B's handoff uptake rather than A's extraction accuracy. The model, temperature, user query, and case wording are held fixed within every comparison.

For each case and world, B receives a gated no-handoff request and a gated valid-handoff request under three arms. **User handoff** and **system handoff** use exactly the same role instruction and artifact sentence; only the sentence's message channel differs. **Typed state** is a separate design package with an explicit application field `ROUTE=NONE` or `ROUTE=<name>` and a conditional role instruction. It changes both representation and wording, so it cannot isolate either component. A fourth probe shows the full world-specific case to the typed-state arm without a handoff. The 8 cases × 2 worlds × 7 requests per world produce 112 planned requests, shuffled with seed 7331. Provider calls are paced at least 2.6 seconds apart. A transient Groq tool-call 400 receives one retry; a 429 stops the run for later resumption.

The primary outcome is strict B behavior: exact `Awaiting route.` before handoff and exact mapped vehicle after it. A paired case succeeds only if both worlds wait before handoff and both give the correct vehicle after it. Full-case leakage is an exact correct vehicle before handoff. Provider failures, empty replies, and formatting violations are separate counts; a failed API call is never scored as waiting. We also record request hashes, full request contexts, model settings, attempt errors, and call order. The user-versus-system contrast is paired by case and world. The typed-state arm is a descriptive package comparison. With only eight cases, any proportions and contrasts remain exploratory; no significance or general-model claim will be made.

The route pairs are fixed in `route-factorial-study.mjs`. They vary route labels, destination, and vehicle mapping while preserving a two-choice decision. The static audit must pass for each arm and pair before any provider call. A failing audit invalidates the study, rather than being treated as a model failure.
