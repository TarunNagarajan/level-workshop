# Model-selected browser witness protocol

Frozen before analysis on 3 October 2026. Use `match-intact` and `mismatch-intact`, whose card signatures differ and UV status matches. Declare the card request as the required reveal action. Build three paired finite-state audits from the actual passport reducer and player serializer: ordinary open-book asset; world-specific injected open-book asset; and an intentionally incomplete injected model that omits asset observations. Bind the asset observations to the exact WebP hashes served in the completed temporal browser study, rather than inventing a textual clue separately.

The ordinary model should certify that the card is the first distinguishing action and return a shortest reveal trace. The asset-aware injected model should return a shortest bypass through `open`, without requesting the card. The asset-omitting negative control may produce a false certificate; compare it to the browser trace and report the disagreement explicitly. Match each selected reducer trace to a prefix of the paired browser action history. The browser trace must show the same first differing action and, for the injected bypass, a GET for the same open-book asset hash. A mismatch is a failed parity result, not a reason to relabel the browser output.

This checks model-selected witnesses on two saved browser action orders. The finite graph is exhaustive only for its first-use action adapter and declared observations. Browser confirmation of selected witnesses does not establish that every modeled transition renders correctly, nor that all browser actions and network channels are represented. Do not turn this into a production certificate badge without broader coverage and source freshness checks.
