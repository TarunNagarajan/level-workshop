# Portable interaction audit bundle

The [schema-v1 compiler](author-audit-bundle.mjs) turns saved paired browser histories into an author-facing witness bundle. It is independent of the equipment and passport scene implementations. The [builder](build-author-audit-bundles.mjs) currently produces [equipment](author-audit-equipment.json) and [passport](author-audit-passport.json) examples; the [generic viewer](author-audit-viewer.html) loads either with `?bundle=equipment` or `?bundle=passport`.

An author declares a fact, two world variants whose correct final answers differ, and the object action intended to reveal that fact. Each browser row supplies the same action history in both worlds, per-stage observation fingerprints, and a screenshot hash. The compiler rejects different paired action sequences, repeated ambiguous stage names, equal final answers, and screenshots whose file bytes no longer match the recorded hash. It computes the first difference separately for visible text, accessibility, rendered pixels, POST action payload, and downloaded GET bytes. A stage before the declared event is `exposed-before-event`; at the event it is `revealed-at-event`; after it is `revealed-after-event`; absent on the saved path it is `unrevealed`. When the path ends without the declared event, any observed difference is early.

The resulting JSON contains `schemaVersion`, `sceneId`, `title`, declared channels, source-report hashes, and an array of scenarios. Each scenario contains `factLabel`, `declaredEvent`, two world labels and different answers, the action path, paired screenshot paths/hashes for every stage, per-stage channel equality, and per-channel first-difference verdicts. The [localization pass](author-audit-localization.mjs) verifies the captured pixel hash against decoded PNG pixels and the captured response hash against its saved JSON. It adds the changed-pixel count and bounding rectangle, changed response field paths, and downloaded-resource paths at each step. The viewer overlays the rectangle only in author mode. This is a pixel envelope, not OCR or proof that a person recognized the clue. The bundle records where the evidence came from; it does not contain model replies or a claim that a human noticed a visual clue. The [rebuild audit](audit-author-audit-bundles.mjs) verifies source hashes and reproduces both bundle bytes. The [tests](author-audit-bundle.test.mjs) check both scene families, malformed paired histories, and stale capture hashes.

For a new sandbox level, generate the rows from its actual versioned reducer and player HTTP route, not from a hand-written copy of the storyboard. Capture both worlds at one common player URL, normalize only opaque IDs and timestamps, and keep the fact values inside the server until the intended action. Record browser network bodies, accessibility state, rendered pixels, and screenshot hashes. Compile the bundle from those captures, inspect shortest bypasses, repair early exposures, and rerun after each revision. Bind the eventual author badge and leaderboard score to the immutable level version and trusted observation event. A contributor-provided bundle is diagnostic input, not an authenticated certificate; production must verify that its source traces came from the frozen version.

This bundle is intentionally a **witness collection**. It describes its saved paths and channels only. Edge coverage can choose which paths are affordable to replay, but a green bundle cannot rule out untested histories, timing leaks, assets omitted from the capture, or a target model that ignores its verified context. A production author UI should display those scope limits beside each verdict.
