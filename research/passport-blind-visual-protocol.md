# Blind four-world browser boundary protocol

The opening-screen and action-order protocol was frozen before the first capture. The complete action-payload and post-action accessibility comparisons were added after that first passing run and are exploratory extensions. Run four isolated local servers, one per passport signature/UV world, in this order: `match-intact`, `match-broken`, `mismatch-intact`, `mismatch-broken`. Each server uses the same port, blind path `/reference/research/preview`, built client, model stub, viewport, and fresh Chromium context. The world is selected only in the server fixture. No account or owner page is opened in the player browser.

At the introduction, capture the URL path, player configuration response, rendered text, accessibility snapshot, same-origin GET response paths and body hashes, image response hashes, and decoded screenshot pixels. All four must be identical. After starting the counter, compare player round and desk payloads after replacing only opaque round/message/event IDs, access tokens, and clock fields with constants. The visible closed scene must have no world-specific text. Request the arrival card, inspect it, and record its rendered signature and pixels. Use the UV lamp and record the inspection note and pixels. Compare the complete normalized card-action response and accessibility snapshot between worlds that differ only in UV condition. In a fresh context, use the lamp before requesting the card, then compare the complete normalized UV-action response and accessibility snapshot between worlds that differ only in signature relation. A signature difference is expected after the card, and a UV difference after the lamp. The card request must not expose UV status.

Negative control: in one isolated rerun, replace the initial passport-cover asset at the same URL with a different existing WebP asset while leaving API text unchanged. The image-response and screenshot-pixel checks must fail at introduction. This tests binary visual divergence, not semantic OCR of an image.

The audit reports exact initial equivalence only for captured player GET bodies, DOM/accessibility text, URL path, and decoded pixels under this fixture. After a round starts, equivalence is up to declared opaque identifiers and clock values, including event IDs and event timestamps. It does not cover other browsers, all click orders, image semantics, screen readers beyond the captured accessibility snapshot, or a live provider. The target static prompt intentionally differs across worlds.
