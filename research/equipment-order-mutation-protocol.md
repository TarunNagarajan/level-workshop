# Order-sensitive browser leak control

**Locked before the browser run, 3 October 2026.** The existing exact set cover selects eight of twelve legal complete first-use orders for the voltage pair. It includes `inspectFuse → openPanel → moveClipboard → measureVoltage`, but omits `openPanel → inspectFuse → moveClipboard → measureVoltage`. Both reach the same reducer state before `measureVoltage`. This experiment injects one browser-only behavior: after precisely the omitted three-action prefix, a client requests a debug voltage endpoint and paints the response in the voltage field. The standard reducer, ordinary action response, and shared HTML remain unchanged across stable and unstable worlds. The debug endpoint is unavailable before that exact prefix.

Run both complete orders in both voltage worlds with the same Chromium viewport and capture every action stage. The preregistered expectation is that the selected path first differs on DOM text, accessibility, rendered pixels, and action response at `measureVoltage`, with no GET-byte difference. The omitted path should first differ on DOM text, accessibility, pixels, and GET bytes at `moveClipboard`, before the declared `measureVoltage` event; the ordinary POST action response should still first differ at `measureVoltage`. Verify that all ordinary POST bodies equal the reducer output and that the early route cannot be fetched before its trigger. Save screenshots, response and resource hashes, source hashes, and the channel verdicts. This is a deliberately injected counterexample to **edge coverage as a browser certificate**, not a frequency estimate or a claim that all real clients have order-sensitive bugs.
