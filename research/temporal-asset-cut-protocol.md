# Temporal asset reveal protocol

The two browser orders, asset conditions, and screen/GET comparisons were frozen before first capture on 3 October 2026. A later exploratory extension compares POST action responses as their own channel. Use two passport worlds with identical UV status and opposite card signatures: `match-intact` and `mismatch-intact`. The claimed first reveal of the card signature is requesting the arrival card. Run each world under two same-URL browser action orders: `open → card` and `card → open`. Run both orders in a clean condition with the ordinary open-book image and an injected condition where the open-book image carries the card signature as visible lettering. The injection uses one image template and varies only the signature text. Keep the player API, client bundle, viewport, and deterministic target stub fixed.

At intro, closed desk, and after each action, capture rendered text, accessibility snapshot, full-page decoded pixels, and the GET resources fetched since the previous stage. Mask only the countdown timer after the round starts. Record each POST action response separately, normalizing only opaque round/message/event IDs, capability tokens, and timestamps before comparing it across worlds. In the clean condition, opening before requesting the card should leave all channels equivalent, and the card action should distinguish screen, accessibility, and POST response channels. In the injected condition, opening first should distinguish the worlds through `/reference-assets/open-book.webp` and screen pixels before any card request, while the POST response remains equal until card. In the card-first order, the card is already the first distinguishing screen action; the later image difference is redundant. The GET-resource channel excludes POST action responses, so a clean card reveal remains `unrevealed` in that channel. Visually inspect the two injected open-book screenshots to confirm the authored text is legible.

The browser trace supplies a concrete shortest *tested* bypass path, not exhaustive reachability over all possible actions. The audit should report a first divergence per channel and whether it precedes the declared action, including the resource URL and action history. It does not infer what a model knows, use OCR, assess human attention, or certify untested action orders. The ordinary asset is not changed in the app.
